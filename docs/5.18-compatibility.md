# Kindle firmware 5.18.x 兼容审计

本轮只实现 firmware 5.18.x 的 `fw518` profile；5.17.x 只参与版本解析测试，不包含特殊适配。统计算法、守护进程、`reading-time.tsv` schema、9.7.5 UI、封面解析与缓存路径均保持不变。

## 修改前实际调用链

安装链：

`RUNME.sh` → 全新安装时 `Install-Native-Reading-Time.sh` → `native-reading-time-daemon.sh`、`/etc/upstart/native-reading-time.conf`、临时旧 UI → `Install-Native-Reading-Time-Optimized.sh` → `/mnt/us/documents/阅读记录.sh`（直接安装优化 UI）与 `/mnt/us/reading-time/releases/9.7.5-test/`。

运行链：

`/etc/upstart/native-reading-time.conf` → `/mnt/us/reading-time/bin/native-reading-time-daemon.sh` → LIPC 读取前台应用、电源状态、当前书元数据 → 追加 `/mnt/us/reading-time/reading-time.tsv`。

`/mnt/us/documents/阅读记录.sh` → 直接加载 `reading-time.tsv` → AWK 生成 `/tmp/native-reading-dashboard.*` 会话缓存 → 可选只读快照 `/var/local/cc.db` → Lua/FBInk 合成 UI → 触摸 Lua → 页面事件循环。

## 修改后安装与启动链

`documents/reading-records-install.sh`（Scriptlet）

或 `extensions/reading-records-installer/bin/action.sh`（KUAL）

或 `RUNME.sh`（`;log runme`）

→ `/mnt/us/native-reading-time-package/install.sh`

→ 原有基础/优化安装器（保留既有原子安装与回滚）

→ `/mnt/us/documents/阅读记录.sh`（薄入口）

→ `/mnt/us/reading-time/bin/launch.sh`

→ `compat/detect_env.sh`、依赖/权限/数据检查、日志捕获

→ `/mnt/us/reading-time/releases/9.7.5-test/bin/reading-records.sh`（原 9.7.5 UI）。

## 运行依赖与系统接口

- 必需 shell 工具：`sh`、`awk`、`sed`、`sort`、`grep`、`date`、`cp`、`mv`、`mkdir`、`chmod`、`cmp`。
- 必需 Kindle 接口：`lipc-get-prop`、`lipc-set-prop`、Upstart `/sbin/initctl`、kindlehf loader、外部 FBInk、Lua。
- 可选：`lipc-wait-event`（锁屏等待优化）、`sqlite3`（进度/目录只读快照）、`unzip`（EPUB 本体封面）、`fbset`（否则回退 sysfs 屏幕尺寸）。
- 未使用：`eips`、Pillow 调用、`cvm`、Java、D-Bus、`appreg`、systemd。没有 PW6/12th Gen 型号硬编码。
- LIPC 属性：`com.lab126.appmgrd activeApp/activeContext/start`、`com.lab126.powerd state/preventScreenSaver`、`com.lab126.yjr.annotations getCurrentBookMetadata`、`com.lab126.winmgr eatTapMode`、scanner full scan/trigger update。

## ELF / ABI 结论

源码目录和历史 `Kindle安装包-v9.7.1-install-fix.zip` 均按 ELF 魔数扫描，没有项目自带 executable/shared library，因此没有可对项目 payload 执行的 `readelf -h` / `readelf -A` 对象。字体、PNG、PGM、Lua、AWK 与 shell 文件均不是 ELF。

FBInk 是 KMC/hotfix 提供的外部依赖，不随本项目分发。诊断脚本会在设备存在 `file` / `readelf` 时，额外记录外部 FBInk 的 ELF header、ARM attributes、program interpreter 与 `NEEDED`；这些工具不存在时只记录“unavailable”，不会为此引入依赖。

## 诊断与隐私

启动失败状态写入 `/mnt/us/reading-time/last-launch-status.txt`，包含 `stage`、`exit_code`、firmware、device、architecture、hard-float 与 profile。统一诊断写入 `/mnt/us/documents/reading-records-diagnostic.txt`，并尽力复制为 `阅读记录诊断.txt`。

诊断只记录环境、文件/权限、命令存在性和最近启动输出；不读取书籍正文、Amazon 账号、token 或密码。

## PC mocked 验证范围

- 版本：5.19.x、5.18、5.18.1、5.18.1.1.1、5.18.5、5.18.5.0.1、5.18.6、5.17.1.0.4。
- 数值比较：5.18.10 > 5.18.2；5.18 = 5.18.0.0。
- deviceType 缺失回退、kindlehf loader、profile 选择。
- 正常启动、UI 非零退出、阶段/退出码、自动诊断。
- 缺失 KUAL/MRPI/SH Integration 标记与可选依赖。
- 安装原子回滚、历史 TSV/旧 release 保留、封面缓存保留、卸载保留数据。
- 原有 UI/统计/详情/封面全套离线回归与发布 ZIP 逐字节校验。

## 必须真机验证

1. 5.18.x 上 `/sbin/initctl` 与 `/etc/upstart` 仍能安装并持久启动追踪服务。
2. 上述 LIPC service/property 名称和值在原生阅读器、锁屏、退出阅读器时保持当前语义。
3. KMC/hotfix 提供的 FBInk 为 kindlehf，并支持当前 OpenType、PNG、区域刷新与 GC16/GC16_FAST 参数。
4. Lua、SQLite、unzip、fbset 的实际路径/版本；缺失 SQLite/unzip 时进度/本体封面降级是否符合预期。
5. SH Integration 是否分别展示 `阅读记录安装`、`阅读记录卸载` 与 `阅读记录`，脚本权限、卸载后索引刷新及输出行为是否正常。
6. KUAL 与 KUAL Next 是否均能解析中文菜单、参数和四个动作。
7. `com.lab126.appmgrd start app://com.lab126.KPPMainApp?view=KPP_LIBRARY` 的 UI 返回行为。
8. Kindle 10th、Paperwhite 10th、Oasis 10th、Kindle 11th/2024 的屏幕、触摸设备发现和旋转行为。
9. 安装失败后的 rootfs 重新只读、Upstart 回滚、scanner 刷新和诊断文件可见性。

在真机结论明确前，不增加 model-specific hardcode，也不为 5.17.x 引入兼容分支。

## 退出清理的唯一实际顺序

`launch.sh:cleanup_runtime_state()` 通过 EXIT trap 作为唯一系统状态恢复入口。INT/TERM/HUP 仅触发退出，fork/PID 窗口仍沿用既有 deferred signal handoff。

完整顺序为：**UI/reader 完成或终止并 wait → 原 preventScreenSaver → 原 eatTapMode → 打开原生 Library → sleep 1 → 原 orientationLock → 释放会话锁**。

| 路径 | 实际末尾命令序列 |
|---|---|
| 正常退出 | UI 自行清理 child，launcher wait 完成；按上面的完整顺序恢复 |
| Lua error | renderer 按基线进入旧 UI；旧 UI 成功或失败后 wait；同一清理顺序 |
| FBInk error | UI 异常退出、回收 owned child；launcher wait；同一清理顺序 |
| touch 初始化失败 | UI 在检查设备/reader 时失败并清理；launcher wait；同一清理顺序 |
| launcher 初始化失败 | 若尚未发起任何属性修改，仅释放已取得的锁；若已旋转，只 Library → sleep 1 → 原方向；若已设置 power/touch，按对应 pending 标志依完整顺序恢复 |
| INT | 活动 UI 存在则取消 handoff、TERM owned UI 并 wait；恢复 pending 属性、Library、原方向，释放锁；状态 130 |
| TERM | 同上，状态 143 |
| HUP | 同上，状态 129 |

竖屏且未临时旋转时不发送 orientation restore。未知原方向且需要旋转时，在任何方向修改之前拒绝。CLEANED 在清理入口先置 1，重复调用直接返回；signal handler 在清理期间不再次启动清理。原 power/touch 值先分别 lipc-get-prop 保存并验证，再设置 pending、发起临时修改；恢复使用保存值，不固定写 0。pending 在请求前设置，保证请求返回途中收到信号时也能恢复；请求失败时无法确定是否部分生效，故仍恢复已保存值。这些系统属性语义与起点相同；launcher 改动仅在锁获取/释放及 owned handoff 路径。

## 安装锁与空间方案

原 installer 在验证设备后、建立快照和 stop daemon 前已拥有 `/tmp/reading-records-ui.lock`。它能拒绝稳定状态下的并发事务和活动 UI，但不能覆盖 bootstrap 和 stale 清理竞态，因此并非完整公共安装互斥。

现在 bootstrap 使用 `/tmp/reading-records-9.7.6-install.lock/owner.$$`。原子 mkdir、PID 目录及唯一 claimant 检查防止空锁重建窗口中两个进程都进入；仅通过 kill -0 证明 dead 的 owner 才允许 rmdir。退出只 rmdir 自己的 PID 目录；正常完成和 INT/TERM/HUP 均在 owned installer 回收之后释放。新共享 helper 同样用 owner PID，在清理 stale 内容前建立自身 claim，拒绝其他 live claimant，并把 UI start/cancel 放在 owner 目录内。旧 live PID 仍受保护；旧 dead-PID 带 handoff marker 的锁可恢复。未知、非项目生成的损坏锁不猜测清理；无法确认持有者时安全拒绝。

第二次点击在共享日志截断和 tar list/extract 之前退出，不 stop daemon、不建 STAGE、不写 runtime、不删除第一次的 tmp，不改第一次日志；只显示“安装正在进行”。没有 flock，没有后台锁进程。

- `/tmp`：bootstrap 在 tar 解包前检查，至少 `ceil(uncompressed_tar_bytes/1024) + 4096` KiB。本包 tar 22,978,560 bytes，当前要求 26,536 KiB。
- `/mnt/us`：internal installer 在 mkdir STAGE、备份、root_rw、stop daemon 前检查，要求 `2 × du(payload) + du(每个将替换的旧文件和同版本 release) + 8192` KiB。只计已知部署目标，不遍历/管理用户历史数据。
- `LC_ALL=C df -Pk` 固定 KiB 与 POSIX 行布局；只接受一条完整设备行、数字总量/已用/可用和百分比，接受标准 1024-blocks 与 BusyBox 1K-blocks 表头。非零退出、命令不可用、空/乱码、负数、缺列、多设备行、错误单位均 fail safe；du 大小失败也拒绝。
- 两种空间失败均保留安装两文件及旧 runtime/daemon，不新建 cleanup，写 install-last.log，并明确 toaster“存储空间不足”。bootstrap 不覆盖 internal installer 的具体错误 toaster。不自动删用户文件、旧 release 或旧恢复快照。

另有创建日志目录/打开日志的 I/O 失败注入，证明即使日志路径本身无法写入，仍提前退出、发送明确 toaster 并保留原 runtime/daemon。存储完全无法写日志时，任何代码都不能保证 install-last.log 落盘；本轮没有另造诊断文件或删除用户数据来满足写日志。

`/tmp/reading-records-9.7.6-installer.$$` 保留。项目中没有目标 5.19 Kindle 的 mount/容量实测；22.98 MB 解包确实需要容量，但不能据此证明该设备 /tmp 的具体 tmpfs 上限。本轮用实际 df 可用量提前拒绝不足，没有猜测迁移到 /mnt/us。预检不预留/独占磁盘空间，其他系统写入仍可能在检查后耗尽容量；此时回滚失败必须保留快照，不能宣称成功。

## 未改动的理论风险与真机边界

没有证据证明短中文 tar 一定在 Windows/macOS USB/MTP 失败；本轮改名来自用户明确的统一 ASCII 原则。没有证据证明目标 /tmp 一定不足；保持路径，以预检判断。Library 先启动再恢复方向这一真实顺序不改为另一种猜测顺序。PID 复用保守地视为 live，会拒绝而不会杀掉其他进程；不引入复杂进程身份管理器。

无 EVIOCGRAB、power-key handler、power-button mapping、消费电源键或终止系统 powerd。只保留既有临时 preventScreenSaver 并精确恢复。必须等待真机的事项仍为：orientationLock 可读性/生效及 Library 实际旋转时序、framebuffer 与触摸坐标同步、原阅读器方向偏好、物理电源键/自动休眠、e-ink 波形/残影、真实 catalog/新书封面及设备识别。不用更多代码模拟这些行为。SIGKILL、断电、损坏存储或 LIPC 永久不响应的系统状态恢复不能由 shell trap 保证。

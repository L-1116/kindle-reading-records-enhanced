# V3 5.18.x 启动兼容热修审计

## 证据与判断

KPW6 5.18.4 和青春版 2024 5.18.1 均已完成安装、进入插件页面，daemon 运行正常，系统顶栏仍响应。这将故障范围压缩到插件的显示进程及其外部运行时。当前没有两台设备的启动日志，无法证实是同一个具体二进制或同一条 FBInk 调用失败；两者可以属于同一类“主体 framebuffer 已写入，后续 Lua/FBInk/刷新失败或卡住而没有回到原生页面”的故障。

旧 launcher 只检查 `lua` 命令存在、FBInk 文件有可执行位，不启动 Lua，也不初始化 FBInk。旧 UI 的首次 `draw_background` 先把 PNG 写进 framebuffer；其后的动态绘制、首次刷新、触摸 Lua 都可能失败。首次刷新返回码没有触发退出；触摸 Lua 非零时被转为正常 `exit`；原先的 legacy UI exec 分支还会卸掉本进程的 cleanup trap。顶栏由系统自身控制，所以主体白屏同时顶栏正常是合理结果，不能从现象反推 daemon 故障。

## 原调用链

`/mnt/us/documents/阅读记录.sh` → `bin/launch.sh` → source `compat/detect_env.sh` → 检查工具、FBInk 可执行位、TSV、入口与少量资源 → `releases/9.7.5-test/bin/reading-records.sh`（来自 `阅读记录-optimized.sh`）→ 屏幕和触摸发现 → 缓存构建 → FBInk 背景写入 → Lua 渲染与 FBInk 动态绘制 → FBInk 首次刷新 → Lua 触摸监听。动态渲染失败时旧 UI shell 可切至 `reading-records-v9.6.3.sh`。

`detect_env.sh` 从 `/etc/prettyversion.txt`，失败时从 `/etc/version.txt` 提取 firmware；`uname -m` 得到机器架构，`/lib/ld-linux-armhf.so.3` 是否存在或架构名带 hf 用于 hard-float 启发式标记。5.18.* 得到 `COMPAT_PROFILE=fw518`；旧代码仅 5.18.1* 得到 `IS_FW_5181=1`。因此旧 5.18.4 属于 fw518、要求 hard-float，但首刷仍走 `fbink -q -f -W GC16 -s`；5.18.1 补丁只将第一次改为 `-q -W GC16 -s`，其余调用不变。

包内的 `releases` 是安装时组装的 shell/Lua/PNG/PGM，并无 Lua/FBInk ELF。Lua 来自设备 PATH，FBInk 来自 KMC、libkh 或 PATH；此前无法仅凭源码断言失败机最终选中了哪个实际二进制。

## 热修调用链

入口 → launcher 覆盖创建 `launch-last.log` → 探测 firmware、kernel、machine、hard-float → 检查 UI 入口、渲染/触摸 Lua、字体、PNG/PGM、TSV → 执行 Lua 并对必需 Lua 文件进行 `loadfile` 语法探针 → 用 `fbink -e` 初始化 framebuffer，但不画图、不刷新 → 如果主候选失败，仅检查设备上实际存在的其他候选并记录原因 → 导出探针通过的 Lua PATH 和 FBInk 路径 → 启动原 V3 UI。

FBInk 候选来自仓库原有的 KMC、libkh 和 PATH 路径；Lua 候选来自 PATH 以及存在时的 libkh/`/usr/bin`/`/usr/local/bin`。不捆绑新二进制，不按 5.18.1/5.18.4 点版本选 runtime。hard-float 仍被记录，但可执行性由实际运行探针判定。探针全部失败则不进入 UI。

5.18.x 全家族首次 GC16 全屏刷新去掉强制 flashing；5.19.x 和旧 firmware 刷新命令保持原状。首次绘制、动态渲染、刷新失败直接非零退出；触摸 Lua 非零也成为非零退出。UI 自身 cleanup 请求 Kindle 原生书库重绘；launcher 在 UI 非零退出时再次尽力释放输入/休眠状态、请求原生书库、提交非强制闪烁刷新并显示 toasterMessage。若 FBInk 本身卡住、Kindle appmgrd 不响应或设备拒绝刷新，shell 无法保证恢复，需真机验证。

原地升级继续使用 V3 既有安装入口和 `9.7.5-test` 目录。安装器不变；已有安装回归验证其保留 `reading-time.tsv`、历史数据、封面缓存和用户配置。此热修没有更改 daemon、service、upstart 或统计/UI 功能。

## 静态问题和生产修改前复现

原启动器必须读取 `eatTapMode`，失败即 `fail "无法保存触摸状态"`；成功后临时写入 0，退出写回所谓原值。旧模拟器直接读取数值文件，将只写属性错误建模为可读写。这导致模拟通过掩盖真实控制流中的启动阻断。

两个实际 Lua 监听器均 `io.open(device, "rb")`，只观察 evdev；调用链为正式 launcher → 优化 UI → runtime-child 的 read_touch_action → 优化触摸 Lua，渲染不可用时 owned legacy child → 同一 runtime-child → 旧触摸 Lua。无 EVIOCGRAB、设备写入或 LIPC 触摸设置。9.7.5 两个入口进入/退出时尽力写入 0，没有读取原值，不能称为恢复原触摸状态。

先仅修正模拟器：只写属性读取返回非零且 stdout 为空，即使隐藏值为 7 也不可读。随后用未修改的真实 5.18 launcher，在 sh/dash、U/R 方向、原值完全缺失/隐藏 0/隐藏 7 共 12 个组合中复现退出码 1、`ERROR: 无法保存触摸状态`，触摸监听尚未启动；横屏清理仍恢复原方向。保存证据在 `build/validation/518-eattapmode-before.json` 和 `518-eattapmode-reproduce.log`，修改前旧包、checksum、历史 suite 与报告保存在 `518-eattapmode-before/`。最终回归保留原启动器的失败复现，不将其记成修复包失败。

参考 5.19 的 `305e42f7` 启动修复及 `341ee3d` CI 工具修复，逐项提取适用改动；没有 merge 或整体 cherry-pick。5.19 真机成功是用户提供的参考证据，不能作为 5.18 已通过的证据。

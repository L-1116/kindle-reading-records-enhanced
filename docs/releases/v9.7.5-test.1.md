# Kindle 阅读记录 v9.7.5-test.1

> ⚠️ **Public Test / 公开测试版：这不是正式稳定版。**
>
> 本版本主要用于 firmware 5.18 compatibility、firmware 5.19 regression，以及新安装器/卸载器的 Kindle 真机验证。请不要把它当作已经确认兼容所有 5.18 / 5.19 Kindle 的稳定版。

## 为什么发布这个测试版

9.7.5-test.1 不是普通功能更新，而是一次 **compatibility + installer public test**。本轮同时有三个目标：

1. 验证 firmware 5.18.x 上能否安装、启动、记录和显示统计；
2. 验证为 5.18 所做的调整没有破坏 firmware 5.19.x，并回归测试新安装体系；
3. 验证“安装 → 使用 → 卸载 → 保留历史 → 重新安装 → 原历史恢复”的完整生命周期。

## 本轮重点测试

### 1. Kindle firmware 5.18.x

这是最高优先级测试环境。希望确认 5.18.x Kindle 是否能够：

- 安装并生成“阅读记录”入口；
- 正常打开并记录阅读时长；
- 正常使用月历、周统计、累计时长、阅读书籍、当天详情、月份详情、最近 8 周和单书详情等主要页面；
- 正常使用书籍封面功能；
- 退出并重新进入后仍保留数据；
- 正常运行新的 installer、launcher 和 compatibility layer。

### 2. Kindle firmware 5.19.x

**5.19.x 也属于本次重点回归测试范围。** 本轮明显调整了安装体系、launcher 和 compatibility layer，因此需要确认：

- 新 Scriptlet 和统一 installer 可以正常安装；
- “阅读记录”可以正常启动，原有统计功能没有 regression；
- 卸载和重新安装正常；
- 历史数据在卸载、重装后仍然保留。

目前不能据此声称“5.19 已确认完全兼容”；仍需要真实设备反馈。

### 3. 新安装 / 卸载体系

本测试包首次同时提供两个独立 Scriptlet：

- `reading-records-install.sh`：在支持 SH Integration 的 Kindle 书库中显示为“阅读记录安装”，用于首次安装、升级和重新安装；
- `reading-records-uninstall.sh`：显示为“阅读记录卸载”，用于卸载程序、删除启动入口和阅读记录相关 KUAL extension，**默认保留阅读历史数据**。

仍保留三层入口：

1. Scriptlet；
2. KUAL；
3. RUNME / `;log runme`。

本轮特别希望用户优先测试 Scriptlet 新安装方式。

Scriptlet 需要 Kindle 已具备相应的 jailbreak / Hotfix / SH Integration 环境。这个测试包不会自动完成越狱，不会自动安装 Universal Hotfix，也不会重写或自动修复 Kindle 的 jailbreak、Hotfix、SH Integration 或 `;log` 环境。并非“任何越狱 Kindle 都可以直接点击安装”。

如果“阅读记录安装”没有出现在书库，这本身就是重要测试结果。反馈时请注明 Kindle 型号、firmware、越狱方式、Hotfix / SH Integration 情况，以及是否安装 KUAL 和 MRPI。

## 本版本主要变化

- 增加 firmware compatibility layer 和环境检测；
- 使用统一 launcher 和统一 installer；
- 增加“阅读记录安装”Scriptlet；
- 增加独立“阅读记录卸载”Scriptlet；
- 保留 KUAL 和 RUNME / `;log runme` fallback；
- 增加自动 diagnostic；
- 卸载默认保留历史，并支持从保留的安装入口重新安装；
- 修复安装、启动、卸载与重装生命周期衔接；
- 保持 9.7.5 已有的统计、详情、封面和封面兼容改进。

可能仍存在以下问题：

- 某些机型无法显示 Scriptlet；
- 不同 jailbreak 环境行为不同；
- launcher / Kindle system API 存在固件差异；
- 旧版 Hotfix / SH Integration 行为不同；
- UI、状态栏或屏幕刷新在不同机型上有差异。

## 安装方法

1. 下载并解压 `kindle-reading-records-v9.7.5-test.zip`；
2. 把解压后的**全部内容**复制到 Kindle USB 根目录，不要只复制单个脚本；
3. 安全弹出 Kindle；
4. 优先在书库点击“阅读记录安装”；
5. 如果设备不支持该 Scriptlet，可使用 KUAL → 阅读记录 → 安装 / 升级；
6. 再不行可使用旧入口 RUNME / Kindle 搜索栏 `;log runme`。

安装前建议备份 `/mnt/us/reading-time/`。首次安装、升级和重新安装都使用“阅读记录安装”。

## 特别需要的测试环境

- **最高优先级：5.18.x** — 验证新兼容层和完整功能；
- **其次：5.19.x** — 验证没有产生 regression，并验证新 installer / uninstaller。

5.17.x 不是本轮正式适配完成或正式支持目标。欢迎愿意尝试的用户提供 diagnostic，但请不要据此理解为 9.7.5-test 已支持 5.17。

## 推荐测试流程

### Step 1：记录环境

测试前请记下：

- Kindle 型号；
- firmware 完整版本；
- jailbreak 方式（如果知道）；
- 是否安装 Universal Hotfix；
- 是否具备 SH Integration；
- 是否安装 KUAL；
- 是否安装 MRPI。

### Step 2：安装

将测试包按上面的说明复制到 Kindle，优先测试“阅读记录安装”Scriptlet。记录：

- 它是否出现在 Kindle 书库；
- 点击后是否成功；
- 安装后是否出现“阅读记录”。

### Step 3：启动

打开“阅读记录”，确认：

- 能否打开；
- 页面能否正常切换；
- 有没有闪退、无响应或显示异常。

### Step 4：统计

打开任意一本书阅读约 1～3 分钟，退出阅读后进入“阅读记录”，确认：

- 时长是否增加；
- 当天是否出现记录；
- 阅读书籍是否出现；
- 月历是否显示；
- 周统计是否正常；
- 累计统计是否正常。

### Step 5：再次启动

退出“阅读记录”，然后重新打开，确认数据仍然存在、UI 能再次打开，没有在首次启动完成后失效。

### Step 6：卸载

点击“阅读记录卸载”，确认：

- “阅读记录”消失；
- “阅读记录卸载”消失；
- “阅读记录安装”保留。

### Step 7：重新安装

再次点击“阅读记录安装”，确认：

- “阅读记录”重新出现；
- “阅读记录卸载”重新出现；
- KUAL 入口（如原本存在）恢复；
- 原阅读历史仍然存在。

### Step 8：继续阅读

重新安装以后再阅读 1～2 分钟，确认新记录能够继续追加到原历史，而不是只能查看旧数据。

## 出问题怎么办

9.7.5-test 新增了自动 diagnostic。如果发生安装失败、启动失败、打不开、入口异常或环境检测失败，请先检查 Kindle 的 `documents` 目录：

- 主要诊断文件：`documents/reading-records-diagnostic.txt`；
- 同内容中文文件名副本（设备允许时）：`documents/阅读记录诊断.txt`；
- 卸载失败诊断：`documents/reading-records-uninstall-diagnostic.txt`；
- 卸载结果：`documents/reading-records-uninstall-result.txt`。

反馈时优先提供 diagnostic 文件，不需要先复制几十张截图。上传前可以自行打开检查。诊断用于记录 firmware、device、dependency、路径状态、错误和 launcher 状态；其中可能包含 Kindle 上的绝对路径与最近一次启动的错误输出。请不要上传书籍正文、Amazon 登录信息、密码、token 或任何个人账号凭据。

## 已知限制

- 5.18.x 仍等待更多真机验证；
- 5.19.x 的新 installer / uninstaller 仍等待更多设备验证；
- 5.17.x 不是本轮正式支持目标；
- 不同 jailbreak、Hotfix、SH Integration、KUAL 和 MRPI 环境可能有差异；
- 未显示 Scriptlet 并不一定代表阅读记录核心程序本身损坏，需要结合环境信息和 diagnostic 判断。

## 数据安全与卸载

“阅读记录卸载”默认删除阅读记录程序、启动入口、相关 KUAL extension、可重建缓存、运行状态和程序日志；它不会修改 Kindle jailbreak、Universal Hotfix、KUAL 本体、MRPI、SH Integration 或 Amazon 系统服务。

默认卸载会保留 `reading-time.tsv`、其备份、阅读统计报告、用户配置和未被安装清单明确认定为程序文件的内容，因此正常情况下卸载后可以重新安装并继续读取原历史。本测试正是要验证这一行为，但测试版仍建议先备份 `/mnt/us/reading-time/`。

感谢参与。我们特别邀请 **firmware 5.18.x 和 5.19.x 用户参与兼容性与新安装体系公开测试**。

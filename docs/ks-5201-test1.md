- 正式入口统一为 `documents/reading-records.sh`，显示“阅读记录”，调用 KS launcher；已确认归属的旧中文入口和旧安装/清理入口在新运行链验证成功后移除。
- 唯一安装清理入口为 `documents/reading-records-install-cleanup.sh`，显示“安装文件清理”。简易安装不另发布旧 KUAL 安装入口。保留已有 KS 强制退出入口作为独立恢复动作，它不属于第二个统计入口。
- 安装、覆盖升级、repair 使用同一多来源识别和服务恢复流程。修复未知型号文件导致的直接安装失败，保留明确的失败日志。

- 保留 KS 原有 UI、灰度素材、触摸 reader/probe、坐标、统计、封面与原计时 daemon。补回 KS 失败日志里的触摸诊断片段。启动器保存并恢复可读取的电源状态，不新增不可读取的 eatTapMode 查询。

## 不按 KS 年份限制安装

只要可靠硬件来源确认 Kindle Scribe，允许继续安装，不要求具体年份或型号处于白名单。`Kindle Scribe 2030`、未知 USID 代码但型号为 Scribe，以及 Scribe Colorsoft 等名称都可以通过安装资格判断。已知 Scribe USID 代码表仅用于型号文件缺失时的识别回退。

识别来源为 `deviceType.txt`、`/proc/usid`、可用的内核设备树型号。序列号只提取共享设备代码，不记录完整序列号、个人后缀或序列号哈希。明确普通 Kindle、来源冲突、Standard 运行残留或完全没有 KS 证据时安全停止；安装过 KS 软件、屏幕尺寸和笔节点本身不能证明设备属于 KS。所有来源都丢失时无法凭空确认硬件型号，这不是年份限制。

允许安装资格不代表已验证所有代际的显示、驱动、FBInk 和触摸。后续环境和功能检查继续执行，不能因识别为 KS 而跳过。不同年份/彩色面板的真机表现需分别记录。

## 事务、清理与数据保护

KS 专用外层安装器沿用已验收 Standard 的事务和 rollback 流程，新增 KS guard 并保留互斥、服务身份验证与恢复前采证。系统分区先检查实际 ro/rw；mntroot 不可用时直接 remount，每次验证真实状态，结束及失败时恢复原状态。失败保留安装文件、必要日志和未成功恢复的资源。

迁移白名单来自实际历史 KS ZIP 的路径、内容校验和及调用目标，不通过显示名称猜测归属，也不执行历史卸载脚本。个人或修改过的未知入口保留；未知文件占用正式入口或强制退出入口时拒绝覆盖。清理保护当前 runtime、历史 TSV、配置、封面、核心日志、服务和无法确认的回滚资料。清理请求书库 scanner，但请求接受不等于索引已收敛。

## 使用方式

在 KS 上解压外层 ZIP 一次，将两个安装文件一起放进 `documents`，弹出 USB 后点击安装。已有 KS 直接覆盖升级，不要先卸载或清空历史。打开“阅读记录”确认可正常使用后，再点“安装文件清理”。不需要命令、修改环境、选择 runtime 或安装诊断版本。

服务进程正常、识别原生阅读正常、真实新时长写入 TSV 是三个独立结论。安装与 ensure 不宣称真实计时已经验证。测试原生阅读、退出、锁屏及重启后继续阅读，检查历史保留与新增记录；真实设备结果与模拟分开记录。自动恢复无法补算停服期间未记录的时间。
